### Sprint Goal

> 建立 Graph Agentic 的底層基礎：
> 1. `nx_graph_edge` 表 — 統一的實體關係邊（自動同步）
> 2. `pgvector` + embedding 欄位 — nx_knowledge + nx_intel 語意化
> 3. Claude Tool-Calling Agent — 可查圖、可語意搜尋，回答跨節點問題

### Architecture Decision

**選擇輕量路線（PostgreSQL-native）**：
- 圖儲存：PostgreSQL `nx_graph_edge` 鄰接表（from_type, from_id, to_type, to_id, relation）
- Embedding：`pgvector` extension + `text-embedding-3-small`（OpenAI）或 Claude embedding
- Agent：Claude claude-sonnet-4-6 + tool-calling（graph traversal + semantic search tools）
- 不引入 Neo4j / LangGraph — 降低架構複雜度

### Graph Schema

```sql
CREATE TABLE nx_graph_edge (
    id          SERIAL PRIMARY KEY,
    from_type   TEXT NOT NULL,  -- 'client','deal','intel','knowledge','contact','plan'
    from_id     INT  NOT NULL,
    to_type     TEXT NOT NULL,
    to_id       INT  NOT NULL,
    relation    TEXT NOT NULL,  -- 'HAS_DEAL','HAS_INTEL','HAS_KNOWLEDGE','HAS_STAKEHOLDER','AFFECTS'
    weight      FLOAT DEFAULT 1.0,
    created_at  TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE (from_type, from_id, to_type, to_id, relation)
);
```

### Agent Tools

| Tool | 功能 | 輸入 | 輸出 |
|------|------|------|------|
| `get_client_graph` | 取得 client 的所有邊（deal/intel/plan）| client_name or id | edges + node summaries |
| `semantic_search` | pgvector 語意搜尋 knowledge + intel | query text | top-k chunks + source |
| `get_deal_context` | 取得 deal 的完整上下文（MEDDIC + intel + timeline）| deal_name or id | deal dict + related intel |
| `list_recent_intel` | 最近 N 天的情報，可過濾 client | days, client_id? | intel list |

### Auto-Sync Rules

建立/更新以下資料時，自動寫入 `nx_graph_edge`：

| 觸發 | 自動建立的邊 |
|------|------------|
| 建立 `nx_deal`（client_id）| `client → HAS_DEAL → deal` |
| 建立 `nx_deal_intel` | `deal → HAS_INTEL → intel` + `intel → AFFECTS → deal` |
| 建立 `nx_intel`（client_id）| `client → HAS_INTEL → intel` |
| 建立 `nx_knowledge`（client_id）| `client → HAS_KNOWLEDGE → knowledge` |
| 建立 `nx_plan`（client_id）| `client → HAS_PLAN → plan` |
